The method behind these apps

All of the apps, the public and the private ones, are built with my own development templates: coding standards, a reference for every AL object type generated from the AL compiler itself, design patterns (polymorphic table logic, per-feature setup and assisted setup, demo data packages, MCP configurations), analyzer rulesets, documentation and testing standards, and checklists. There are three variants, for greenfield products, customer projects and NAV reimplementations. I improve them with every project, and they are what I bring to a team.

Dataverse Integration Redesign new Dataverse, Sales and Field Service integration on swappable interfaces

Microsoft's Dataverse, Dynamics 365 Sales and Field Service integration for Business Central, redesigned around swappable interfaces instead of hard-wired event subscribers: every integration table mapping picks a handler, and every step of the sync flow (filter, field transfer, insert, modify, coupling, conflicts, follow-ups) is an interface method of that handler, so a dependent app can add or replace the handling of one table pair without touching anyone else's.

It covers Dataverse (customers, vendors, contacts, currencies, salespeople), Dynamics 365 Sales (products, units, price lists, opportunities, sales orders, posted invoices, account statistics) and Field Service (resources, customer assets, project journal posting, service orders), the Dataverse actions on 32 pages, the CRM Redirect page and its own Field Service reset. 19 defects found in Microsoft's code are documented, each with the test that shows the redesign avoids it.

bc-dataverse-integration-redesign
Manufacturing Advanced new Guardrails and capabilities for Business Central manufacturing

The manufacturing counterpart of Warehouse Advanced: guardrails on the standard production flows where Business Central lets problems through, and capabilities it does not have. Release pre-flight checks an order before release (dead routing links, flushing without tracking, missing bins, uncertified designs, flushing against warehouse handling); WIP control finishes the orders that should have been finished and reconciles each order's WIP with the G/L; refresh protection records and restores what a refresh overwrote; standard cost drift, planning insight, a shop floor terminal, engineering change orders with approval workflows, and capacity-aware finite loading complete it.

Every module is switched off until enabled, swappable through interfaces, exposed as API pages and MCP configurations with agent instructions, and covered by a test app.

manufacturing-advanced-bc
