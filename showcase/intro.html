A map of a family of Microsoft Dynamics 365 Business Central products, built every night straight from their AL source code and API contracts. It shows where the apps meet: whether they can be installed side by side, which standard tables, codeunits and events several of them depend on, which features have no tests, and how much of an API contract is implemented.

Why it exists

Partners who sell several apps meet the same problems at the customer. Two per-tenant extensions that share an object ID cannot be installed together, and apps that hook into the same posting routines affect each other in ways no single repository shows. This page checks all the apps at once.

How it is made

bc-knowledge-graph reads each repository: object declarations, table fields, event subscriptions, API pages, feature documents, test plans and OpenAPI/AsyncAPI contracts. It links them into one graph. Nothing is compiled, deployed or run, and no Business Central environment is needed.

Use it on your own apps

The tool is open source. Point it at your repositories to get this page for your apps, ask Claude about them in plain language through its MCP server, or explore the graph in Neo4j. Get started on GitHub.
